# AIO Graphics Test v2.2.0

Fullscreen for every test, an unattended benchmark sweep, a Vulkan fix for Wayland compositors, and a new small **CursorTest** tool.

## ✨ What's new

- **Vulkan runs on compositors without IMMEDIATE.** An uncapped Vulkan run asks for the IMMEDIATE present mode. A Wayland compositor without tearing control (Bannerlator's Wayland session) never offers it, and AIO exited with **"Present mode unsupported"**. It now falls back to **MAILBOX** (still uncapped), then **FIFO**.
- **True fullscreen for every test.** The corner button / **F11** now makes whatever is running — all eight graphics backends, the DX11 scenes, demos, scaling tests, tools and a running benchmark — one borderless window over the whole screen with the swapchain at the screen's size (before, only the HDR card could). That is the one-window case a compositor can put straight on the display (**zero-copy**). The fullscreen HUD shows `fullscreen: yes (W x H at 0,0)` when it's met. **F11 / Esc** or the Exit Fullscreen pill drops back to the view you left.
- **Benchmark report** gains the AIO version, "Present: uncapped", and per test the render size and fullscreen state. It is also written as `AIO-Graphics-Test_bench_report_latest.txt`.
- **Unattended `--sweep <sec>`.** Runs the eight graphics backends for `<sec>` seconds each (default 15) in fullscreen with vsync off, writes the report and closes. `--apis=gl,dx9,…` runs only the backends you name. A watchdog ends a run that stops rendering for 60 s and keeps the rows that finished.
- **HUD side-channel.** During Run / Run All / `--sweep` the app publishes which backend is being benchmarked, so Bannerlator's Fusion HUD labels it correctly.
- **New: CursorTest.exe.** A separate small 64-bit tool for checking an emulator's colour mouse cursors without a game: colour quadrants (channel order), soft alpha shadow, 64×64 size, an animated cursor, standard arrow and hidden tiles, plus a GDI strip (text, gradient, AlphaBlend, StretchBlt) to spot 2D drawing regressions.

## ▶️ Command line: per-API runs and sweeps

Launchers already know which exe to start, so paste **only the arguments** into the game's launch options (see [where to paste](#where-to-paste-the-arguments)). From a Windows command prompt or a Wine terminal, put the exe name in front; those full commands are in the fold-outs. Start the app from its own folder: results go to `AIO Results\Benchmark\` in the folder it is started from. The 32-bit build takes the same arguments. Every box has a copy button.

### One API at a time (true per-API numbers)
Each run opens that API's own window with a real present, benchmarks for 15 seconds, shows the result window and closes 5 seconds later.

Options for `--cube` runs:
- `--bench <sec>`: timed benchmark, then the result window and the report files. Leave it out to just run the cube.
- `--autoclose <sec>`: closes the result window, and with it the app, after `<sec>` seconds. Leave it out to keep the result on screen.
- `--vsync`: present with vsync. The default is uncapped.
- `--scene phong` or `--scene meshshader`: alternative Vulkan scenes.

Result files in `AIO Results\Benchmark\`:
- `AIO-Graphics-Test_bench.csv`: the latest run only, overwritten each time. Line 3 holds `avg_fps`, `min_fps`, `max_fps` and `low1pct_fps`; per-frame times follow.
- `AIO-Graphics-Test_bench_<API>.txt`: `avg|min|max` FPS, one file per API, kept between runs.

### All eight APIs, one after another
In a launcher, change the API in the launch options and launch again for each one. From Windows or plain Wine, a `.bat` file next to the exe runs them all as separate launches (not tested in every launcher):

```bat
@echo off
for %%a in (vk gl dx12 dx11 dx10 dx9 dx8 dx7) do start "" /wait AIO-Graphics-Test-64bit.exe --cube %%a --bench 15 --autoclose 5
```

The CSV ends up holding only the last API; each API's `.txt` summary stays.

### In-app sweep (`--sweep`)
All eight backends, 15 seconds each (default 15, maximum 600), fullscreen, uncapped. It writes the sweep report (also as `AIO-Graphics-Test_bench_report_latest.txt`) and closes. A watchdog ends a backend that stops rendering for 60 s and keeps the rows that finished.

```text
--sweep 15
```

Only the backends you name (`vk gl dx12 dx11 dx10 dx9 dx8 dx7`), always run in that order:

```text
--sweep 15 --apis=gl,dx9,dx11
```

In the sweep (and the app's Benchmark view) every backend except D3D11 renders off-screen and is shown through the app's D3D11 window, so those rows include a GPU→CPU copy and run through DXVK's D3D11. Use the sweep to compare builds or settings of the same setup; use the `--cube` runs above for per-API numbers.

### Where to paste the arguments
- **DroidDeck:** the game's **Launch options**.
- **Steam** (added as a non-Steam game): **Properties > Launch options**. With an environment variable, use `%command%`:

```text
VAR=value %command% --cube dx11 --bench 15 --autoclose 5
```

- **Winlator / Bannerlator:** the shortcut's **exec arguments**.
- **Plain Wine** (terminal):

```text
wine AIO-Graphics-Test-64bit.exe --cube dx11 --bench 15 --autoclose 5
```

Print the OpenGL and Vulkan adapter info and exit:

```text
--gpuinfo
```
