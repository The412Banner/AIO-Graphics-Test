# AIO Graphics Test v2.1.0

Adds an **HDR test card**: a quick, light way to check that HDR10 really reaches your screen, and to see exactly what the game side (DXGI / DXVK) is told about that screen — without running a heavy game.

## ✨ What's new

- **HDR test card (Display Tests → HDR).** A Direct3D 11 test that switches the window to a real HDR10 swapchain (flip model, 10-bit, PQ / BT.2020) — the same path an HDR game takes through DXVK — and switches back when you pick another test. If HDR isn't available it shows SDR and tells you why, instead of failing. Open it straight from a shortcut with **`--hdr`**.
- **What DXGI says about your screen.** The card reads `IDXGIOutput6::GetDesc1` (colour space, bit depth, peak / full-frame / minimum brightness and colour primaries) and gives a plain verdict: **"DXGI reports your screen (~1345 nits)"** when the screen's own description reached DXVK, or **"DXGI reports DXVK's stand-in (1499/799/0.01)"** when it didn't.
- **Primaries verdict.** The colour primaries are shown as **your screen's colours (from the layer's description)**, with the gamut they're close to, or as **DXVK's P3 / Rec.709 stand-in**. The stand-in is matched exactly, so a real screen description is never mistaken for it.
- **Patterns you can judge by eye.** Brightness patches at **80, 203 (SDR white), 400, 600, 1000 nits, your screen's peak and 10000 nits**; a **PQ ramp** from 0 to 10000 nits that stops getting brighter where your screen clips; **10-bit vs 8-bit banding strips** (steps in both mean something in the chain is 8-bit); a slowly moving **sun** at your screen's peak on a dark sky; and **BT.709 vs BT.2020** colour rows.
- **HDR10 / scRGB / SDR modes.** Tap to switch between HDR10, scRGB (16-bit float, converted by DXVK for the screen) and plain 8-bit SDR for a straight A/B.
- **Vulkan surface probe.** Asks the window system directly — no DXVK involved — which formats and colour spaces it offers, whether HDR10 comes with a 10-bit format, and whether HDR metadata can reach the compositor.
- **True fullscreen for zero-copy.** On the HDR card the corner button makes one borderless window over the whole screen (taskbar included), with the swapchain at exactly the screen size — what a compositor needs to put the frames straight on the display (**zero-copy**). The header shows whether that's met, next to the local time so photos line up with logs.
- **Always-current report.** Everything is saved to **`AIO Results\HDR\AIO-Graphics-Test_hdr.txt`** (plus a copy in `Z:\usr\tmp\` when that folder exists), rewritten after every change and **every 5 s**, so it's current even when the emulator closes the app.
- **Clean exit.** Closing the app while the card is open no longer tries to rebuild a swapchain on the closed window.
- **Light on the phone.** Vsync with a 60 fps cap by default (30 fps or no cap in the Values panel) on a mostly black card.

## 🧪 Tested on
- **Samsung Galaxy Fold (Adreno 840)** with Bannerlator's Wayland HDR: HDR10 on, 1345 nits from the screen's description, the primaries verdict, fullscreen zero-copy, 120 fps with frame generation in HDR10, report saved.
- An **Adreno 735** phone (892 nits) and the **ASUS ROG Phone 9 Pro** (1207 nits).

HDR needs DXVK with HDR enabled (`DXVK_HDR=1` — Bannerlator sets it when its HDR output setting is on) and a screen that offers HDR10.

## 🎨 Two builds
Ships **64-bit** and **32-bit** as before — use whichever matches the DLLs you're testing (the 32-bit build reaches the container's 32-bit DXVK/VKD3D/ddraw set).

## ⚠️ Reminder — how the API is reported (unchanged from v2.0.0)
Every backend renders off-screen and composites through one surface, so an external/emulator HUD may mislabel the API while AIO runs. AIO's own on-screen readout is authoritative; Bannerlator's latest Fusion HUD shows the true per-test API.
