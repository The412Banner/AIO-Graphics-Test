# AIO Graphics Test v2.3.1

A small fix on top of 2.3.0: the **DX11 scene windows keep drawing while you resize or move them**. Same tests, same command lines, same downloads.

## 🔧 Fixed

- **Resizing a DX11 scene window.** Windows runs its own loop while a window is being sized or moved, and the scene stopped drawing until the mouse was released: the new area stayed unpainted (in Bannerlator's Wayland session it showed stripes) and the picture kept its old size until release. A timer now draws frames during the resize, so the picture follows the new size live, and the window gets a black background for the moment before the next frame. Applies to every DX11 scene (Spinning Cube, Upscaler Test, Cityscape, …); the other APIs' windows are unchanged.

## 🧪 Tested

On a Pocket FIT (Adreno 750) in Bannerlator (Wayland session, DXVK), dragging the right edge of the 640×480 D3D11 cube window with a held mouse button: the cube was redrawn at the new size at about 100 fps during the drag (no stripes) and was back at its normal frame rate (about 2,500 fps) right after release, in four runs. No crashes.

## ⚠️ Known / not tested

- Not tried on real Windows or in other emulators.
- In one early test run the frame rate read 0 for about a second right after the mouse was released; it did not happen again in the four runs above.
- 2.3.0's note about the Cursor Test showing one plain arrow on every tile in Bannerlator's Wayland session: that was Bannerlator / Wine, not AIO. It is fixed in Bannerlator's code and in the Bannerlator Wine layers' code, but not released yet in either.
- Everything else from [2.3.0](https://github.com/The412Banner/AIO-Graphics-Test/releases/tag/2.3.0) applies.

## 📦 Downloads
- **AIO-Graphics-Test-64bit.exe** and **AIO-Graphics-Test-32bit.exe** — use whichever matches the DLLs you're testing (the 32-bit build reaches the container's 32-bit DXVK / VKD3D / ddraw set). Both include the Cursor Test.
- **CursorTest.exe** (64-bit) — the same standalone tool as in 2.2.0.
