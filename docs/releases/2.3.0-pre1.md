# AIO Graphics Test v2.3.0-pre1 (pre-release)

> **Pre-release** for testing. The latest stable release stays **2.2.0**.

A new **Upscaler Test** chart, a launch command for **every** test in the list, and the **Cursor Test** built into the main exe. One 32-bit and one 64-bit exe; no separate CursorTest.exe needed.

## ✨ What's new

- **Upscaler Test** (Scaling Tests, `--cube dx11 --scene upscale`). One labelled, static chart for comparing an emulator compositor's upscalers (SGSR, FSR, NIS, RCAS, CAS, …): run it below the screen resolution, then switch the upscaler. Regions: a fan of 37 aliased 1 px lines (0–180° in 5° steps), zone plate, Siemens star (48 cycles), 1 / 2 / 4 px checkerboards, 1 px bitmap text (white on black, black on white, double size, yellow on blue, low contrast), line pairs (vertical / horizontal / 45°, 2–6 px periods), hard grey edges and an 8-step wedge, six saturated colour pairs (slanted edges + 2 px stripes), ramps (grey, dark 0–32, red, green, blue, hue, dark hue) and soft noise / 1 px grain. Its pixels depend only on position and render size, so screenshots taken at different times can be compared pixel for pixel. **M** or `--motion` adds a slow pan and zoom.
- **A launch command for every test.** Each entry of the right-side test list can be started directly, like the cube tests: `--cube dx11 --scene <name>` for every DX11 scene, scaling card and showcase, `--hdr` for the HDR card, `--cursortest` for the Cursor Test, and `--open <name>` opens the app on any list entry (`--open disk-speed`, `--open zone-plate`; case, spaces and punctuation are ignored). The full table is in the README.
- **Cursor Test in the main exe.** Listed under **Display Tests** next to HDR; **Open Cursor Test** or `--cursortest` opens it in a window of its own. Both bitnesses.
- **Window options for DX11 scenes.** `--width W --height H` sets the client size, `--fullscreen` makes one borderless window over the whole Wine desktop at its size, `--nohud` hides the FPS bar (for pixel-identical screenshots). Without them a scene opens in the same 640×480 window as before.
- **The app's own fullscreen from the command line:** `--fullscreen` without `--cube`.
- **The benchmark result box stays on top**, so it is also visible over a `--fullscreen` scene.

## ▶️ Upscaler Test command lines

Paste only the arguments into the game's launch options.

Static, whole Wine desktop, no FPS bar (for screenshots):
```text
--cube dx11 --scene upscale --fullscreen --nohud
```

With the pan / zoom:
```text
--cube dx11 --scene upscale --fullscreen --motion
```

Benchmark like the other scenes:
```text
--cube dx11 --scene upscale --fullscreen --bench 15 --autoclose 5
```

## 🧪 Tested

On a Pocket FIT (Adreno 750) in Bannerlator (Wayland session, DXVK): Upscaler Test static / motion / `--width 960 --height 540` / benchmark (64 and 32 bit), static frames pixel-identical over 24 s with `--fullscreen --nohud`, Combo Card benchmark (64 and 32 bit), Cursor Test via `--cursortest` (64 and 32 bit), `--open upscaler-test`, `--open cursor-test`, Cityscape in the default 640×480 window, `--hdr`, the app's `--fullscreen`. No crashes.

## ⚠️ Known / not tested

- Once, on the very first start of this build, the screen was black 15 s into a static `--fullscreen --nohud` run; it did not happen again in 21 screenshots over three later runs.
- Not tried on real Windows or in other emulators. The chart's shader is compiled at start-up by the system's D3D compiler; a failure would show as a message box when the scene opens.
- The moving chart is resampled nearest-neighbour, so some 1 px lines double while it moves (by design; use the static chart for comparisons).
